# M8「驿路」活体测试脚本（用户执行）

> 前置：feat/m8 构建（`scripts/run-app.sh`）。需要本机 Node（`node -v` ≥18）。
> GitHub 场景需要你的 PAT（classic，repo 只读权限即可）。
> 验收基准 = V2 设计 §5-M8：两个真实 server、白名单+审批生效、kill 后 block 不死、重启重试成功、存量全回归。

## 第 1 组 · 驿站注册与生命周期（设置页）

1. 设置 → MCP 驿站：三件精选（filesystem/github/playwright）逐个「添加」。filesystem 会让你选目录——选一个测试用文件夹。
2. github 行填入你的 PAT → 「存」→ 出现「已配置」签。
3. 点 playwright「重启」：预期 启动中 →（首次可能停摆：超时文案会告诉你在下载依赖）→ 再点重启 → **在营 · 20+ 工具**。
4. 故意添加一个自定义驿站（名字 bad-test，命令 `no-such-cmd`）→ 重启 → **停摆 + 红色人话线索**（env: no-such-cmd: No such file or directory）→ 删除它（确认弹窗提到清凭据/清启用）。

## 第 2 组 · 营地启用 + 伙伴授权（显式白名单语义）

1. 营地首页左栏「驿站」：勾选 github 与 playwright。
2. 伙伴编辑器：新建/编辑一位伙伴 → 工具区下方「驿站工具（MCP）」按 server 分组 → github 点「连接列出工具」→ 勾选 `list_issues`/`search_issues` 类两三件；playwright 勾 `browser_navigate` + `browser_take_screenshot`。保存。
3. **反向验证**：另一位从未编辑过的存量伙伴（白名单还是老格式）不应看到任何 MCP 工具出现在其行动中（提示词工具区无 mcp__ 名）。

## 第 3 组 · 一次行动内双 server 实战（验收核心）

1. 新行动（标准档）：目标类似「查 anthropics/claude-code 仓库最新 5 个 open issue 归纳成 issues.md；再用浏览器打开 https://example.com 截图存工作目录」。指派上面授权过的伙伴，选工作目录。
2. 预期：伙伴调 `驿站·github / list_issues`（feed 有活动行）→ 写 issues.md；调 `驿站·playwright / browser_navigate` + `browser_take_screenshot`。
3. **审批面**：标准档下 MCP 工具（write 级）不弹审批；把行动档位切到「谨慎」再重试一张卡 → MCP 调用应弹审批卡片，批准后继续。

## 第 4 组 · kill 与复活（保守失败语义）

1. 行动进行中（伙伴正用 playwright 时最佳）：终端 `pkill -f "@playwright/mcp"`。
2. 预期：卡片受阻（feed 出现「驿站停摆」节拍）；**行动不死**（其他卡照常）；卡片详情有「到设置页重启」引导；设置页 playwright 显示停摆。
3. 设置页点「重启」→ 在营 → 回行动详情点该卡「重试」→ 卡片完成。

## 第 5 组 · 存量回归

1. 无 MCP 的营地跑一个老行动（读写文件/web_fetch/run_shell）——一切照旧，审批矩阵照旧。
2. 向导对话 + 组队提案 + 收营蒸馏照常。
3. 紧急收哨（Cmd+.）时驿站进程一并停（`ps aux | grep mcp` 无残留）；恢复出哨后新派发能自动拉起驿站（不卡 down）。
4. 重启 App：驿站回「未启动」（进程态不持久化，符合预期），启用勾选与凭据保留。

通过后打 `m8` tag（顺序 m4→m5→m6→m7→m8）。
