# Coding 牧场视觉设计 V1（小剧场牧场化）

- 日期：2026-07-15
- 状态：方向已定稿（用户已确认），资产产线进行中
- 前置：`2026-07-04-agentloop-macos-mvp-design.md` §11.2/§11.3（小剧场与动效体系）、Coding 牧场产品化改造（2026-07-14，见 `docs/collaboration/tasks/2026-07-14-coding-ranch-mvp/`）

## 1. 背景与问题

2026-07-14 的产品化改造把用户可见术语全面牧场化（伙伴→牛、启动行动→放牛、资料投喂→喂牛/反刍、名册→牛棚），小剧场在 UI 中改名「Coding 草原」。但视觉未同步：`CampfireTheaterView` 仍是篝火夜景 + 环形围坐，与「草原/牛群」文案形成隐喻断层。本设计补齐视觉层，并为后续动效资产升级（spec 预留的 Rive/Lottie 路径）提供视觉基准。

## 2. 已定稿的设计决策（用户确认于 2026-07-15）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 主视觉风格 | **黏土微缩（claymation 3D 微缩舞台）** | 氛围与「治愈系放牛」气质最合；像素风被明确排除；扁平插画风保留为 SwiftUI 自绘参考 |
| 牧场基座 | **方圆角悬浮基座** | 空间分区自然（牛棚区/草场区/水塘区），适合分区叙事 |
| 小牛阵容 | **v1（性格外放版）** | 眨眼/傲娇/皱眉等表情差异大，个体辨识度高 |
| 场景与主题的关系 | **正交，不绑定** | 草原/牛棚是**状态**（放牧中/归棚休息），亮暗是**主题**；亮色主题下也有牛在牛棚，暗色主题下也有牛在放牧。资产按 {草原, 牛棚} × {白天, 夜晚} 2×2 矩阵产出 |

## 3. 隐喻映射（视觉元素 ↔ 产品概念）

| 牧场元素 | 产品概念 | 代码锚点 |
|---|---|---|
| 小牛（七色） | 伙伴 / Agent | `Companion`；颜色对齐 `CompanionAvatarView` 七色调色板（紫/青/珊瑚/粉/蓝/绿/琥珀），延续「换色即换伙伴」 |
| 放牧（草原上各自忙碌） | 行动执行中、工作卡推进 | `TaskRunView` 小剧场（现 `CampfireTheaterView`） |
| 吃草 / 饲料槽 / 干草卷 | 喂牛 → 反刍（资料消化）；干草卷=待反刍队列 | `FeedService` / `RuminationService` |
| 牛棚（隔间休息） | 待命 / 名册 | `CowRosterView` |
| 基座（悬浮草地舞台） | 牧场的「场」；空基座=尚未放牛的待机态 | 本次新增 |

小牛状态动作与 `CompanionAnimState` 对齐：敲笔记本=working、冒问号=thinking、举蹄=asking、撒花=celebrating、Zzz=napping。注意「吃草」不是现有 anim state——它由喂牛/反刍（`FeedService`/`RuminationService`）的进行时状态驱动；现有 `idle`/`scratching` 两态对应的牛姿态在逐只立绘规格（§7）中定义。**不变量：小剧场动画是真实事件流状态的可视化，不是装饰动画。**

## 5. 落地路径（渐进，不推翻现有实现）

1. **氛围资产先行**：静态插画进 app——牛棚（名册页头图）、空基座（空态插画）、放牧图（可作新手引导/关于页）。需要在 `Package.swift` 增加 resources 声明（现无任何 bundle 资源）。
2. **伙伴动画仍走 SwiftUI 参数化自绘**：`CompanionAvatarView`/`CampfireTheaterView` 的绘制体系不动，概念图作为自绘升级（篝火→草原基座、围坐→放牧布局）的视觉基准。
3. **再评估重资产方案**：Rive/逐帧/视频循环，仅当 1、2 验证观感后进入。

亮暗主题处理：同一场景出日/夜两版（或对静态资产做色调分层），主题切换只换色调层，不切换场景语义。

## 6. 风险与约束

- image2image 的角色一致性有限，跨图微小走形不可避免；概念阶段可接受，量产立绘需以单图 + 人工筛选把关。
- 生成消耗即梦积分（2026-07-15 余额 30066）；视频类单次成本显著高于图片，批量前先单发验证。
- seedance2.0 可能容量受限或要求 Web 端合规确认（`AigcComplianceConfirmationRequired`），失败时降级 seedance1.5pro 重试。
- 大图不入 git；后续如需团队共享，另行决定存储位置。
