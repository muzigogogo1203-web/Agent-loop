# M5 正式测试脚本 — 多营地 / 崩溃恢复 / 预算收尾 / 打包（含 M4 一并验收）

前置：在 feat/m5 上 `scripts/run-app.sh` 启动（M4 的全部内容都在本分支——建议 M4 的 7 组场景直接在这里跑，脚本见 `2026-07-06-m4-live-test.md`）。
本篇只列 M5 新增场景。

## 1. 多营地=频道（M5-0）

1. 侧栏底部「新营地」→ 起名（如「写作间」）+ 自定义向导人设 →「扎营」→ 直达新营地首页,侧栏出现新分区。
2. 在新营地里发起行动(分区里「新行动…」或首页右上按钮)→ 表单顶部显示营地 chip → 出发 → 行动出现在**该营地分区**下。
3. **频道隔离**:新营地首页的笔记本应该是空的(看不到别的营地的笔记);问新向导「营地情况怎么样」→ 只报本营地的行动。
4. 旧营地(「我的营地」)一切如常:老行动/笔记/向导对话都在。
5. 营地首页标题右键「重命名营地…」→ 改名生效;完成的行动出现在首页左下「往期行动」,侧栏只留进行中。
6. 向导组队提案确认后,新行动落在**该向导的营地**分区。

## 2. 崩溃恢复(M5-1,spec 验收:杀进程重启续跑)

1. 发起一个多卡行动,等第一张卡进入执行中(转圈)。
2. **强杀 App**(⌘Q 或活动监视器强制退出)。
3. 重新启动 → 该行动自动继续:原先执行中的卡回到就绪并被重新派发,最终跑完到可收营。详情面板里旧 run 显示 interrupted、有「crash_recovery」中断记录。
4. (进阶)向导提案点「就这么办」后立刻强杀 → 重启后该提案应回到「等你拿主意」状态,可重新确认,不会凭空多出行动。

## 3. 预算收尾线(M5-2)

1. 设置页把「默认预算」改小(比如 20000)→ 发起一个会烧 token 的行动。
2. 预算耗尽后:行动页出现琥珀「预算见底了」banner,行动暂停派发,小队动态有对应条目。
3. 三选各试一次(可分多个行动):
   - 「续 Nk」→ 立即恢复执行;
   - 「就地收成果」→ 未完成的小目标取消、已完成的保留,行动变为可收营,收营蒸馏照常;
   - 「放弃」→ 行动结束。
4. 测完把默认预算改回 200000。

## 4. 上下文压缩(M5-3,机会性观察)

超长行动(单卡 30+ 轮)才会触发。若遇到:小目标活动时间线出现「上下文变长,压缩了早期过程继续赶路」,之后伙伴仍记得此前的关键产物路径并正常收尾。不必刻意制造,记录是否见到即可。

## 5. 打包分发(M5-5)

1. `scripts/package-app.sh` → 产出 `dist/AgentLoop.app` + zip。
2. 双击 dist 里的 .app(或拷到「应用程序」)→ 正常启动、图标是营地帐篷、「关于」显示 v0.5.0。
3. 它与 `scripts/run-app.sh` 的开发版共用同一数据库,数据互通。

## 6. Reduce Motion 复核(M5-4)

系统开「减弱动态效果」→ 打字指示变静态「…」、提案卡片/抽屉/笔记本无动画但功能完整、小剧场静态姿态。
