## Test semantics

The test uses two real temporary GRDB `DatabaseQueue` instances with foreign keys enabled. One migrates fresh to the current `AppDatabase.migrator` head. The other migrates to the literal historical checkpoint `v17-p1-engine-coordination`, then migrates to the current head.

After both real migration paths run, the test requires the registered, fresh persisted and upgraded persisted heads to equal the literal `desktop-goal-workflow-v1`. These `#require` gates stop the test before dependent schema assertions when the migration is absent, avoiding a cascade of missing-table/index issues.

Once the required head exists, the test requires the two carrier tables and partial unique index to exist with the correct SQLite object kinds, then asserts:

- Fresh and V17-upgrade migration receipt sequences are equal.
- Fresh and V17-upgrade carrier schema snapshots are equal.
- The complete normalized literal DDL for `desktop_goal_context` matches the approved SQL, including live/redacted retention checks.
- The complete normalized literal DDL for `desktop_goal_operation` matches the approved SQL, including owner kinds, phases, redaction checks and its context foreign key.
- The complete normalized literal DDL for partial unique index `desktop_goal_one_pending` matches `inputId WHERE phase='prepared' AND ownerKind='userMutation'`.
- Both tables' literal ordered column shapes match.
- Context has no foreign keys; operation has exactly `inputId → desktop_goal_context.inputId` with SQLite `NO ACTION` update/delete behavior.
- The pending index covers only `inputId`, is unique and is partial.
- Both fresh and upgraded queues have an empty `PRAGMA foreign_key_check` and `PRAGMA integrity_check == ['ok']`.

Expected values are literal and hand-derived from the approved SQL rather than generated by production code. The test references only existing `AppDatabase.migrator` and GRDB APIs, so its intended RED is the missing real desktop migration/head/schema, not a missing Swift symbol or stub.
