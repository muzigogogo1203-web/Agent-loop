## Deterministic CLI152 held-pipe lifecycle

The parent helper consumes stdin, creates a private acknowledgement pipe, and `posix_spawn`s its own staged executable in `held-stderr-child` mode. The child must **inherit the backend parent's existing process group**, not create a new group; backend TERM/KILL must own the whole scenario. Child stdin and stdout are closed or redirected to `/dev/null`; stderr remains the inherited backend stderr pipe. Only the explicit handshake descriptor is additionally transferred, with checked file actions and all other auxiliary descriptors closed. The holder sends one acknowledgement byte after initialization, closes the handshake descriptor, and blocks with default TERM disposition. It has no self-expiry timer.

After reading that byte, the parent closes its acknowledgement descriptors, writes the fixed parent-ready marker to stdout, and exits 0. It does not wait for the holder, which must outlive its parent in the same group. Backend exact-parent reaping activates the existing 50 ms drain grace; stderr cannot reach EOF because its initialized descendant still owns the write end. The backend must report `.pipeDrainIncomplete`, terminate the remaining process group, and complete checked cleanup. The holder must not ignore TERM: this is the drain/descendant test, not the separate KILL escalation test.

Test body first requires the exact parent-ready marker and then requires stream failure `.pipeDrainIncomplete`; it must retain the existing aggregate watchdog budget from launch, not restart a larger timeout after readiness. Use an actual `ContinuousClock` deadline rather than 200 sleeps if preserving the intended two-second budget; do not claim this is the same wall-time behavior as the old iteration counter. No test-body cancellation is requested on the normal path; the existing owned cancellation-and-consumer-join recovery still runs on failure. Assert no unexpected stdout/stderr and preserve group absence, child reap observation, socket cleanup and signature call order. Failure cleanup must handle spawn-before-acknowledgement too, including descendant group termination; its primary error remains visible.

Natural parent exit is structurally guaranteed by the fixed parent mode after successful holder acknowledgement; `.pipeDrainIncomplete` plus absent body cancellation distinguishes the held-pipe path from the observed TERM/143 watchdog recovery. Do not invent a status-0 exit frame on an error stream: the production stream currently does not yield `.exited` when finalization throws. If exact exit status is additionally required, add truthful general lifecycle exit-status diagnostics; do not weaken evidence type semantics or add a test-only product callback.
