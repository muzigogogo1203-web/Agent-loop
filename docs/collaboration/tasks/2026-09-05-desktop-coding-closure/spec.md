## 本次交付

延续 `../2026-09-05-product-takeover-baseline/spec.md` 与长期 master spec 的方向，在现有代码上交付一个可安装、可实际操作的桌面验收候选。

固定用户路径：选择营地 → 输入要完成的目标 → 教练形成可编辑的共同理解与成果要求 → 明确确认开工 → 查看真实执行/待处理状态 → 打开产物与验证证据 → 验收或退回 → 回到营地查到成果与来源。

喂牛/反刍保留为知识入口，不能静默代替目标执行。营地创建、归档/恢复及自建牛移除应有可发现入口与明确影响说明；已有来源删除/反刍重试错误必须可见且可恢复。不能借管理优化删除真实内容、移除系统牛或绕过活动任务保护。永久营地删除是否具备完整执行合同，先核对现有实现；不以普通归档冒充永久删除。

## 完成标准

- 默认无过滤 `swift run RunTests` 通过；修复需有可解释根因与有意义的回归证据，不降低超时断言或把整套测试改成串行来掩盖问题。
- `swift build --product AgentLoopApp -Xswiftc -warnings-as-errors` 通过；产物打包、嵌套 helper、资源和签名证据对应当前源码。
- 主路径接入现有应用/领域工作流，状态可追溯；空输入、重复提交、用户取消、缺少运行配置、失败重试与重启恢复有匹配风险的验证。不得用本地假成功替代 Provider、执行或验收。
- 反刍和管理入口可发现、反馈及时，失败信息包含可排查上下文；危险操作在用户确认后才发生。
- 以独立状态目录做真实 App 壳启动与关键 UI 交互验证，完成职责隔离代码/产品复核。
- 提供本地验收包、简短使用/验收步骤、已知限制和完整证据。候选交付不等于用户已验收，更不自动等于 P1/P2 已正式 Accepted。

## 权限与非目标

不改长期目标用户、北极星、像素牧场身份、权限/数据隔离不变量；不做云端、移动、硬件、公开发布或新商业系统。本地构建/打包是交付步骤；不提交、推送、合并、公开发布、付款或操作真实用户数据。开发验证使用隔离数据和可控测试供给，不读取真实密钥、不调用付费 Provider。需要真实外部动作时只暂停对应分支并请求具体授权，继续可安全完成的内部工作。

## 执行分段与进入门

1. **稳定执行底座**：先用一次现有二进制的默认并发运行和最多两次栈采样定位，再按证据修复共享 I/O/清理问题；并行只做只读方案研究。严格告警清理单独审查，避免与生命周期改动混在一起。
2. **贯通主流程**：复用已有 Goal/Input/Coach/Outcome 控制器，明确界面状态与持久化映射；具体接口在读取现有代码后形成实施子计划并独立复核。运行底座红灯解决前不宣布进入下一正式阶段。
3. **管理与反馈收口**：围绕原始反刍/删除诉求核对已实现能力，补入口和状态反馈，不扩建无关功能。
4. **验收候选**：默认全量、严格构建、迁移/兼容等变更所需门、隔离 UI/启动/资源检查、独立审查和本地打包。用户验收时再确认真实成果质量；内部 fixture 证据明确标识。

每段写明可审查文件范围、失败路径、验证命令与结果。普通根因假设被反证时调整方案并留记录；不反复重跑同一无信息实验，不在任务之间要求用户再次批准已确认方向。
