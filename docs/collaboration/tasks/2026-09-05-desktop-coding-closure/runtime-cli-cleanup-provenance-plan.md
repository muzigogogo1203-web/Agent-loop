## Invariants and review focus

- Failure state is exact generation, never a global execution-ID map. Reused execution IDs cannot inherit it. Existing shared cancellation owner remains the sole cleanup operation.
- Publication is immutable and single-shot. A producer's genuine non-cancellation error, natural success or terminal winner is preserved. Registration after publication cannot rewrite it. Original cancellation caller firstError precedence remains.
- Only a canceled outer task's CancellationError can be substituted. This intentionally does not promise to distinguish every simultaneous producer-thrown CancellationError while the same task is canceled; no actual non-cancellation failure is overwritten.
- Existing early continuation success/terminal-sink finish sites remain untouched. The targeted cancellation catch throws before finishing the outer continuation, so its error is emitted only after canonical publication. Do not finish the stream from resolveCancellation or change success into failure after it was delivered.
- Cleanup failure remains observable through the cancellation claim and the uncanceled execution consumer as its original typed error; no raw error text, provider content or secrets are logged. Existing outcome/lifecycle observation sites remain.
- Review source call sites for the two private signature changes, including closure-return semantics and lock ordering. No synchronous resume while locked and no new lock acquisition under registry lock beyond existing generation publication order.
