## Source-grounded assessment

The current `resolveCancellation` saves the cleanup error locally, cancels the outer task, waits for generation outcome and outer settlement, then delivers the saved error to the cancellation claimant. The outer task independently publishes its caught cancellation error and finishes the stream from that raw result. The proposed exact-generation cause registration and atomic selection address this mismatch without sacrificing the cancellation needed to settle an open producer.

The existing generation has a private NSLock, immutable outcome, monotonic terminal authority, launch phase and shared cancellation-owner state. Recording the first non-cancellation cause only under cancellation authority while outcome is nil fits those ownership boundaries. Registration is generation-local, so reused execution IDs cannot inherit it. `.terminalWinner` never enters the cleanup-owner branch. Late registration is inapplicable but the unchanged cancellation resolver still throws its original first error; no error delivery is silently converted to success.

Selection inside the existing publication lock is the correct atomic boundary: duplicate-outcome and phase preconditions remain; a raw failure may be replaced only when it is CancellationError, the exact outer task is canceled, and this exact generation already holds the cleanup cause. Natural success and real non-cancellation producer errors remain unchanged, and already published outcomes remain immutable. Checking cancellation at the publication call is intentionally not a proof of causality for every simultaneous producer-thrown CancellationError; the plan states that limitation rather than claiming universal attribution.

There is one generation-publication call site in the registry (`CliEngineAdapter.swift:3786`) and one registry-publication call site in the outer Task (`:4078`). Returning the selected result through both private layers makes the generation's stored result, resumed outcome waiters, outer stream error and task result consistent for the substitution path. Merely normalizing one surface or normalizing outside the publication lock would be incorrect; the plan explicitly excludes both. The registry's closure-local early return must leave the enclosing method free to return the selected result, as the plan already requires.

Publication currently releases the generation lock before entering the registry retirement lock. The planned record and select operations must preserve that order and resume continuations outside the lock. Existing retirement identity checks, claim acknowledgment, owner settlement, and outer-task retention are unchanged. No new task, callback, cancellation count, wait, asynchronous seam, or public protocol is required.

Keeping internal outer cancellation, generation-outcome wait, outer-task result join and settled markers is necessary: the existing stubborn driver explicitly leaves the producer open while throwing cleanup failure. Skipping cancellation could strand the resolver. The proposed repair reports cleanup failure honestly and does not reinterpret adapter-task settlement as evidence that an operating-system process was terminated.

Existing early stream finishes do not require expansion of this change. The targeted CancellationError catch throws before finishing the outer continuation, allowing its selected error to be delivered after publication. Non-cancellation failures under cancellation ownership also rethrow. Successful/prelaunch/terminal-sink paths that finish early keep their results and authority; the plan does not attempt to replace success or to finish from the cancellation resolver. Existing winner/prelaunch/reuse coverage remains relevant to verifying those preserved boundaries.
