3. **Errors remain attributable.** `CliMechanicsCleanupError` retains the original body error object and each labelled cancellation/stream/observation failure. 4. **Resource certification is non-destructive and identity-bound.** The existing inspector adds only successful SIGCONT observations under its existing lock; failed sends and unrelated child snapshots are not used as identity evidence. Certification requires exactly one positive observed PID and equality with successful cancellation PID/group evidence. PID and group checks use only signal 0; `waitid(P_PID, ..., WEXITED | WNOHANG | WNOWAIT)` cannot consume another owner's wait status, and retries only EINTR. Socket absence is checked with `lstat`/ENOENT. A live/reused PID, wrong group, waitable child, permission error, missing continuation or socket error fails certification and retains the fixture.

5. **Deletion follows observations.** All four affected tests enable checked setup cleanup before launch, disable removal immediately before the owned helper, and restore permission only when resource observations pass. Thus an unresolved child cannot be hidden by deleting its fixture; a body failure with confirmed resource absence can clean up its own files. Defer reports the actual checked-removal error without replacing the thrown primary. `removeChecked()` attempts both socket-authority closure and exact fixture-directory removal, preserving both errors when necessary. The legacy `remove()` and its unrelated callers remain byte-unchanged.
