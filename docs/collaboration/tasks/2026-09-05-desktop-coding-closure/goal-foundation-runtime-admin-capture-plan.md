# One authorized target-only kernel-wait capture plan

> **For agentic workers:** Use superpowers:subagent-driven-development for the diagnostic helper task. Root alone owns compilation, local authentication, the one measured workload and evidence retention. No commits.

**Goal:** Obtain one bounded kernel/user wait stack from a newly owned CLI347 test child without reading user camp data or broadening sampling to the system.

**Architecture:** One AppleScript authenticates `/usr/bin/true` through the local system dialog, then performs ordinary-user target discovery. In the same script it invokes a tightly checked capture helper with administrator privileges. Only that helper's one fixed spindump invocation samples a test child. Apple documents a five-minute authentication grace period confined to that same script; no sudo cache or persistent privilege changes are needed.

**Tech Stack:** Existing reviewed C observer identity/path helpers, macOS libproc, spindump, AppleScript and host Ruby 2.6.10.

**Spec:** `goal-foundation-runtime-child-checkpoint.md` and the user's 2026-09-07 explicit agreement to the immediately preceding request: one administrator-level diagnostic, only temporary project test processes, no camp records, no password in chat.

## Design facts and bounded deviations

Local `spindump(8)` says `-onlyTarget` limits sampling, not merely report ordering; plain PID alone only orders the system-wide report. The ten-second tool limit reserves finite report processing after one second of sampling; it does not extend the test's three-second ready deadline. [AppleScript command reference](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_cmds.html) documents authentication scope. This is diagnostic evidence infrastructure, not product behavior; no new product test count or feature-completion claim follows from its checks. Existing checkout preservation and no-commit instructions override generic skill worktree/commit/cleanup defaults.
