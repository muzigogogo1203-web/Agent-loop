# 075 FD fixture ownership diagnosis

Status: **the unsafe fixture's dup2 caused a guarded-FD violation and the kernel killed the full runner.** Correct the fixture before another full run. This investigator performed read-only source/log analysis and wrote only diagnosis/plan artifacts; no build, test, app launch or source change was performed.

Its line 1299 reports an issue at `CliBackendTests.swift:3270`: `stdoutResult == -1` was false. This is a **failed expectation of EBADF**, not an observed EBADF syscall error. `runtime-repair-full-events.ndjson` contains 63 lines: 62 lifecycle events and a metadata record. The subsequently retained `runtime-repair-full-crash.ips` identifies PID 95860, `EXC_GUARD`, subtype `GUARD_TYPE_FD`, violation `CLOSE` on guarded FD **304**, and termination namespace `GUARD`. Faulting thread 15 (ID 1710560, cooperative queue) contains `dup2` → `p1f1d075AssertNoSecondDrainClose` line 3190 → surviving-group helper line 3272 → composition line **3527**, the `.abortSuspended` invocation → 075 test line 3543. `runtime-repair-termination-system.log:5–8` records the matching guard violation and kernel signal-9 termination at 23:44:58.909–23:44:59.057. For example, helper 6's stdout/stderr enqueue-to-entry deltas are approximately 0.264/0.241 ms. These are observed improvements for these owners, not full runtime acceptance. They explain why this run reached FD checks beyond the earlier helper-6 join failure.

## Proven source defect

`p1f1d075AssertLiveDrainOwnership` (`CliBackendTests.swift:3033`) transfers both read descriptors to the real drain and clears them from the fixture's cleanup arrays. After finish joins the workers, the fixture queries the old numerical values with F_GETFD and expects EBADF. The surviving-group helper (`3208`) makes the same checks at `3262–3271`, then invokes `p1f1d075AssertNoSecondDrainClose` (`3171`).

After owner closure, a descriptor number is no longer reserved by this fixture. A concurrent database, socket, pipe or other open can reuse it legitimately. A query of that bare number cannot distinguish the original open description from a replacement. Consequently, an EBADF assertion on a released number assumes exclusive FD-table activity that the default concurrent test runner does not provide.

The second-close fixture has a stronger ownership violation. At `3190`, `dup2(source, target)` forcibly replaces the target even if another owner now holds it. Closing that replacement sentinel in the defer compounds the damage to any owner that continues to use the recycled number. `#expect` at `3270–3271` records an issue and continues; it does not prevent this subsequent destructive operation. Changing it to a throwing precheck alone would still leave a check-then-replacement race.

The intended second-close assertion is meaningful: install an owned sentinel at each old drain number, invoke finish again expecting managedPolicy, and prove the sentinel remains open. The unsafe part is claiming those numbers by unconditional replacement while unrelated tests share the FD table.

The concrete scenario permitted by the source is: drain closes N; another owner opens and receives N; fixture observes N open; fixture dup2 attempts to replace N. The crash proves that final operation hit guarded FD 304 and caused process termination in the abort-suspended fixture. The guarded owner correctly prevented the unauthorized close. The evidence does **not** identify which framework/resource owned FD 304 or show that the original drain failed to close. No further identity guess is needed to fix the fixture's destructive claim of an unowned descriptor number.

## Recommended minimal correction

Keep this as a narrowly planned `CliBackendTests.swift` fixture change, with independent review before full acceptance. No production drain changes are selected by this evidence.

1. Add a distinct, validated child environment mode at the **very start** of the existing 075 test, before `p1f1d075AssertR9DCompositionContract()`. The child runs only the three FD-sensitive helpers: live-drain ownership, surviving-group run, and surviving-group abort. It then records explicit completion evidence and returns to the Testing runner so recorded assertion failures still determine a nonzero exit. Do not reuse the closed-stdio flag or route this child through the general composition routine, which would recurse. Normal composition delegates those helpers to the isolated child; the other composition helpers and existing help/closed-stdio tests remain covered.
2. Self-exec the current verified RunTests executable with the exact 075 filter and explicit fixture mode/evidence paths. Do not spawn `swift run` or build from a test. Give the child no real workspace/database/provider work. Retain stdout/stderr in unique fixture files, verify its actual exit status and distinct completion markers, and report missing evidence, launch failure or nonzero status as test failure. If events move to the child, record its PID and include that PID in the parent's lifecycle extraction; parent-only logs must not be described as proving child drain closure.
3. Make the new spawn/wait owner a named native thread with an async continuation so the parent test suspends. Give the child an explicit bounded watchdog derived from this fixture's aggregate existing limits and startup allowance, without changing the helpers' one-second joins or four-second assertion. On timeout/cancellation, retain the primary error and complete exact-owned-child termination/reap and file cleanup. No kill of guessed PIDs/process groups. This is a new containment limit, not an increase to a test's existing deadline.
4. Remove the unconditional target replacement even inside the child. If open already returns the desired target, it is owned. Otherwise use atomic free-slot allocation such as `fcntl(source, F_DUPFD_CLOEXEC, target)` and require its returned descriptor to equal target. If it returns a higher descriptor, close only that actually acquired descriptor/source and fail explicitly as a fixture collision; never close the occupied target and never retry or silently weaken the assertion. Process isolation removes unrelated tests but does not prove framework/diagnostic activity can never open descriptors. Free-slot allocation makes that residual collision fail safely rather than corrupt another owner.
5. Preserve the original output bytes, open-writer timeout, second successful join, processGroupSurvived checks, four-second bound, stop count, zero active workers, reap-attempt check, both EBADF assertions, managedPolicy on repeated finish, sentinel-alive checks and checked owned-FD closure. Child isolation must not turn a child assertion failure into a successful marker-only result. Preserve full-suite concurrency; a `.serialized` annotation on 075 would neither reserve the process FD table nor isolate it from other suites.

Bounded validation should demonstrate all three helpers execute in the isolated PID; child assertion/error/status evidence propagates to the parent; the sentinel helper never closes an occupied unowned target; focused 075 passes; and then the default authoritative suite is rerun with complete parent/child evidence. A tiny controlled test can reserve a target itself and require the free-slot allocator to report collision while its owned target remains open, without any unrelated shared FD manipulation. Do not introduce a machine-saturation reproducer or broad test serialization.

This recommendation addresses the proven guarded-FD termination mechanism and its preceding misleading EBADF observation. A fix has not yet been implemented or verified, and this diagnosis makes no claim that all remaining runtime failures are resolved. The executable one-file plan is `runtime-fd-fixture-plan.md`.
