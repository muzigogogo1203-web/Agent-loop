## Concrete findings resolved by the extraction

1. **Atomic capture and original receipt are implementable.** `InputGoalStore.swift:27` already creates its replay plan/prepared command and commits input, parsing work, domain receipt, events and outbox under one `pool.write`. Extracting that body to the specified transaction-taking overload lets the new carrier and ordinal-0 receipt share the same transaction, without nested writes or duplicate domain SQL. `DomainEventStore.swift:21` returns the actual safe command result; its stored-receipt path validates the receipt/event/outbox graph before returning. `InputCaptureReceiptV1` really is `CampSafeCommandResultV1`, which is Codable and Equatable. No invented metadata wrapper or conversion of an InputEnvelope into a receipt is needed.

2. **Journal/replay boundaries match real types.** `CaptureInputCommandV1` is only Encodable and excludes its envelope from payload coding (`Domain/InputEnvelope.swift:481`). The separate Codable capture intent and whole-command canonical bytes/hash correctly retain the missing envelope and caller-owned identities. An exact replay can return the original capture receipt after parser progress without demanding the old aggregate head. The extraction explicitly requires current graph validation, rejects mutation under the same identity, and leaves the submit operation prepared until the future fixed coach session exists. Receipt append and original-stage immutability are distinct, concrete operations; A1 does not need a generic dispatcher, future stage success, or Provider execution.

3. **Scoped reads use the existing graph.** Input/camp ownership, fixed goal/source-input joins and fixed session/goal joins are representable with the actual records. `CoachSessionRecord` also has `inputId`; coach work is `kind=.coach`, `aggregateType="goal"`, aggregateId=goal.id, campId=goal.campId, with canonical `CoachTurnWorkInputV1` containing both goalId and sessionId (`CoachUnderstandingStore.swift:1387`). Therefore the required exact-graph implementation must check those payload/session joins as well, and reject pre-existing reserved-ID collisions or wrong joins even before conversion. Optional goal/session means they may be absent; it is not permission to expose a colliding unrelated record. These are direct applications of the extraction's “No other goal's work/records” invariant, not additional functionality. A1 can return a truthful captured input and queued parser work with no goal/session.

4. **Retention hooks and replay checks are correctly placed.** The actual cancellation mutation updates the input inside `DurableWorkStore.cancel` (`InputGoalStore.swift:406`), and completed deletion uses `executeOrdinary`'s Database-bearing mutation (`:656`, `:676`). Both accept carrier redaction in the same transaction. The existing event-store replay path bypasses these mutations; checking carrier retention after the receipt path returns, still inside the write, is necessary and explicitly required. That replay check must validate and reject inconsistent live carriers, not call redaction to silently repair them. Safe receipts must be strictly decoded/validated before preservation; original text, command bytes and stage payloads disappear with requestJson/resultJson/contextJson. Legacy inputs without carriers remain a no-op. No ingestion-deletion or post-goal deletion seam is needed.

5. **The historical V17 correction preserves its assertion.** `outcomeContractMigrationRemainsPresentUnderV17Head` really uses latest-head `p1dDatabase("literal")` while asserting V17 and 79/208/84 (`OutcomeContractTests.swift:406`). Replacing only its setup with a DatabaseQueue migrated up to V17 and using queue.read retains the literal checkpoint. `SQLiteMigrationCompatibilityTests.swift:307` already uses this mechanism. Shared latest-schema helpers, V17 SQL and old count constants need no change. New fresh/upgrade/idempotence/rollback assertions belong in the new migration suite. The proposed conflicting-table failure injection exercises the new migration transaction without production hooks or changes to the frozen historical schema.
