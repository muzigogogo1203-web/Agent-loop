# 产品接手与桌面 Coding 收口

日期：2026-09-05。状态：方向及日常决策授权已获用户确认；工程完成状态以本任务报告为准。

## 用户确认与产品方向

用户确认由 Codex 接手产品的一号位职责，自主负责产品设计、优先级、优化、实现和交付；能根据事实作出的日常决定自行处理，实质性拿不准的问题可以与用户深入交流。此授权替代旧的“Claude 规划、Codex 仅实施”角色限制。

长期产品与系统不变量仍以 `docs/superpowers/specs/2026-07-25-personal-ai-ranch-master-spec.md` 为准。个人 AI 牧场面向 AI 原生独立创作者，Coding 是首个旗舰场景。下一阶段聚焦可日常使用的桌面 Coding 工作系统：

目标输入 → 教练与共同理解 → 确认成果契约 → 持续执行 → 独立验证 → 用户验收 → 项目记忆。

营地承载长期项目上下文；牛是长期身份，引擎可更换；像素牧场保留为真实工作状态与陪伴的呈现，高密度操作进入工作台。喂牛/反刍作为知识输入能力保留，并入一致的目标工作流程。云端、移动、硬件与生态遵循长期路线，不在本轮扩张。

## 决策与权限

- Codex 可在已确认方向和安全边界内决定普通、可逆的产品与技术取舍，制定有界计划并自主执行；重要变更由职责隔离的 agent 独立复核。
- 更改北极星、目标用户、隐私/权限原则或核心产品不变量，遇到证据不足而所有实现路径均依赖猜测，须与用户交流。
- 产品负责人授权不等于 commit、push、merge、release、公开消息、支付、真实用户操作或破坏性数据操作授权。不得自行读取密钥、调用付费 Provider 或删除用户内容以“验收产品”。
- 既有安全门和验收门继续有效。修正文档状态不等于关闭阶段，不把本轮局部复核冒充整个历史实现已通过独立审查。
- 阶段编号是路线索引；每轮交付必须包含用户可感知的目标、明确范围和可核查证据。不得靠不断增加前置工程任务拖延实际产品体验。

## 三个交付里程碑

1. **可信版本基线**：工作目录、源码身份、构建产物和测试证据对应；准确列出历史遗留验证缺口，消除当前角色和阶段入口误导。首个有界步骤见本目录 `product-takeover-baseline-plan.md`。
2. **一条完整桌面路径**：默认目标入口连接现有共同理解/成果契约内核；执行状态、待处理与回营验收依据同一事实源；牛的工作状态来源于实际执行；来源与成果可追溯。先作端到端切片，再拓展其他入口，不整体重写。
3. **真实任务验收**：遵循 master spec §25 的“P2 — 电脑端教练到成果金路径”内部门，至少 3 个真实已验收成果、2 个营地、2 种成果类型，其中至少一个 Coding 成果和一次真实 CLI 端到端执行；包含退回/返工、取消、失败及重启恢复证据。真实凭据、目录和外部动作在权限明确时进行；合成测试不能替代用户验收。

## 本轮有界交付

本轮仅完成接手约定、基线取证和验证缺口的准确归类，不实现新用户流程，不修改 Swift/数据库/测试源码，不宣布 P1-F1、P1 或 P2 Accepted。

运行一次默认权威全量测试；若失败，保存全部输出，按失败用例做一次定向复核及根因调查。不得以过滤/串行通过替换默认全量门，不靠循环重跑把失败刷绿。不明确的根因进入具名后续修复事项，而不是掩盖或猜测修复。

在现有 `.build` 上验证 App 构建并以独立预览状态目录启动，核对包身份、签名、实际进程与资源。预览只证明本地启动，不证明真实 Provider/用户旅程可用。保留原始历史日志；更正旧报告时使用带日期的勘误，不改写历史输出。

完成定义：接手与入口文档一致，历史六项失败记录完整，本轮测试/构建/启动证据存在且结论准确，修改前后源码哈希一致，独立复核通过，留下明确下一步。若测试或构建仍红，只能完成“基线审计”，不能称“可信版本基线已验收”。
